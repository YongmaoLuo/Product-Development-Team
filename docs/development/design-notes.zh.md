# 设计说明

一些承重、但容易被误当成附带管线的决定。每一条都曾经是某次真实故障的成因 —— 这就是
它被写下来的原因。

## 两个独立的完成信号

任务只有在**agent 自己的报告与它声明的 `test_command` 退出码一致**时才算完成。
任何一个单独都不够；交叉验证取多数判决。

诱惑在于相信报告，因为它读起来顺、而且 agent 是唯一知道它想干什么的东西。反例正是
这条规则存在的全部理由：一份写得很漂亮的总结配一条返回非零的命令，不算完成；一条
退出码为零、但**命令本身就选错了**的，也不算。两个信号单独都不充分，因为它们**以
不同方式出错**。

## 空 diff 是警告，不是失败

早期有一道门禁会把任何没产生 diff 的任务硬判失败。那对整个一类合法工作是错的：交付
物是一个**结论**的审计类任务 —— 一个行号、一次 import 形状的验证、一份性能基线 ——
而不是一处改动。

失败模式很具体：这类任务被反复重试，直到计划彻底搁浅。现在它们会被识别出来（声明
`verification_only`，或按关键词判定），并交给**二次审计**比对规格的验收标准与提交的
答案，而不是依赖一次代码改动本会带来的运行时证据。

配套的另一半：非审计任务出现空 diff 是一条**警告**，操作者可以 grep 到它，而不是
静默通过。移除硬失败不等于移除信号。

## 到处都是有界的循环

这个系统里每一个重试循环都有上限，而每个上限都有一条比上限本身更有意思的提前退出：

- **验证轮次**在连续两轮以**完全相同**的验证点集合失败时提前停下 —— 修复没起作用，
  继续下去只是烧预算走到同一个地方。
- **任务重试**在反复失败后拆分子任务，而不是重复一次一模一样的尝试；循环检测器会
  停下"一直以同样方式失败"的任务。
- **子进程超时**杀掉整个进程组，而不只是直接子进程。命令经过 shell 运行时，
  `subprocess.run(..., timeout=N)` 做不到这一点：直接子进程是那个 shell，真正干活
  的东西活得比它久。

一个没有提前退出的循环不是"更彻底"，是一个没有主人的预算。

## `running` 是一个声明，不是证据

状态字段是由某个可能已经死掉的线程写下的。字段写着 `running`，意思是"最后一个写入
者这么说" —— 而当你真的出事时，这正是你所处的状态。

所以系统会拿这个声明去和文件系统对质：最新验证日志、执行结果文件、轮次报告的修改
时间。一个远超任何单步该花的时间都没有产出任何东西的进程，会被报成**卡住**，而不是
继续显得健康。同样的推理也适用于 `/health`（进程还在服务 HTTP 吗？）与
`/health/data`（它真的能读自己的库吗？）—— 一个服务完全可以对前者完全健康、对后者
已经死了。

## 状态 / 原因的契约

有几个停止条件是按**状态值**识别的，不是按 reason 字符串。这是刻意的：reason 字符串
是散文，它们会被改名，而比较它们的守卫会在有人改进措辞的那天静默失效。这件事真的
发生过 —— 改名之后收敛判据不再匹配，在那个版本发布期间一直是坏的，每一轮都烧完了
整个预算。

当一个条件需要被机器识别时，给它一个属于契约、并被测试钉住的值。

## 运行态只有一个目录

状态库、它的 WAL 兄弟、boot 计数器、关闭备份，一起放在一个 gitignored 目录下。它们是
一个整体，理由不是整洁：boot 计数器和备份目录的路径是从数据库的父目录推导出来的，
所以一次局部搬迁会造出"一个进程读它、另一个进程写它"的局面。

这类 bug 的一般形式是**从 `__file__` 多处重新推导同一个路径**。状态库路径曾经被推导过
九次，其中两处已经漂移过 —— 每一处**在写下的当天都是对的**。它现在只声明一次，并由
一道静态门禁守住。见[配置](../operations/configuration.md)。

## 注释用来解释，不用来叙事

注释可以说代码做什么、为什么。它不可以引用某个人、点名一个兄弟仓、或者叙述某台机器
上发生过什么 —— 最后这条读起来像证据，而它恰恰是读者**唯一无法核对**的那类陈述。

失败史改由测试来承载，那是对的地方：一道门禁的 docstring，读它的正好是那个即将改动
它所保护之行为的人。
