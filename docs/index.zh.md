# Product Development Team / 产品开发团队

一个 spec 驱动的 **agent harness**，用来替代原本需要几十个人才能组成的一个完整
产品开发团队 —— 从一句话想法走到经过验证的交付，全程由一名操作者驱动。

你给它一行需求。它澄清需求、写下可评审的 PRD、按需设计架构与测试策略、生成任务
图、**并发地执行任务**，然后对着自己产出的文档**并发地验证结果** —— 把失败反馈
成修复任务并重新验证，直到验收标准成立或者循环预算耗尽。从需求分析到最终测试
验收，整段是一条可审计的流水线，而不是一次对话。

## 重点不是"AI 写代码"

能把提示词变成 diff 的工具很多。这里不同的是：**每一步都留下结构化产物，而系统
是对着这些产物被评判的**，不是对着它自己"我做了什么"的总结。

这带来三个你能观察到的后果：

* PRD、架构文档、测试设计在**动手之前**就是可评审的。每个决策点是一条 CPEA
  记录（Context / Problem / Evaluation / Action），评审者看到的是选择背后的
  证据，而不只是选择本身。
* 执行由**两个独立信号**判定：agent 自己的报告，**与**它声明的 `test_command`
  退出码。任何一个单独都不够。
* 验证读前面各阶段产出的文档，拿运行中的代码去比。一个只问"测试过没过"的验证
  器，发现不了"测试是照着错误的需求写的"。

## 环境要求

Python 3.11 环境，以及 `PATH` 上有一个 Claude Code CLI。服务是本机工具：它以你的
身份、在你的机器上运行，不是为共享或公网托管设计的 —— 在把它指向回环之外的任何
地方之前，先读[运行它](operations/running.md)。
