# 安全

## 信任模型，直说

这是一个**单用户本机工具**。它以你的身份、在你的机器上、用你已经拥有的权限跑命令。
它不是被设计成人与人之间的边界的，它内部也没有任何部分应该被那样读。

实践中的含义：

| 性质 | 后果 |
|---|---|
| 无认证 | 任何能到达该端口的人都能驱动这个实例。 |
| 无用户隔离 | 每个计划、产物、凭据都是共享状态。 |
| 以你的身份运行 | 子 agent 的命令拥有你对文件系统和网络的访问权。 |
| 默认只绑回环 | 除非你设 `PDT_HOST`，它没有在监听网络。 |

request guard 保护什么、不保护什么，以及如果你确实需要它跑在回环之外该怎么办，见
[运行它](operations/running.md)。

## 什么被保护了，什么没有

**被设计保护的：**

- **浏览器来源的访问。** 你恰好开着的某个网页没法驱动这个实例。机制在
  [运行它](operations/running.md)里；一句话版本是：guard 让攻击者的请求变成
  **浏览器**拒绝发送的那一种，而不是服务端拒绝回答的那一种 —— 所以知道请求头的值
  也没用。
- **DNS rebinding。** 解析到回环的主机名会在 `Host` 头上被拒。
- **带凭据的文件。** 携带 provider 凭据的临时文件会被写进私有目录、用私有模式；
  而一旦需要它的进程退出，凭据就被替换成脱敏占位符。
- **进程列表里的通知 secret —— 前提是钥匙串路径已启用。** 两个通知 secret 可以改为
  从独立钥匙串读取、经文件描述符投递，于是 `ps eew` 与 `KERN_PROCARGS2` 看到的是 fd
  号而不是 secret。这是可选开启、默认关闭的：没走过迁移的安装仍然从环境变量读它们，
  而 `secrets verify` 正是用来区分这两种情况的。见[钥匙串迁移](operations/keychain-migration.md)。

**没有被保护，也不打算被保护的：**

- **以你的用户身份运行的本地进程。** 你能读的它都能读。这一类工具全都如此；把**机器**
  当成边界，而不是把应用当成边界。
- **一个照着它读到内容行事的子 agent。** 子 agent 会摄入 plan 文件、仓库文件、命令
  输出，而它为了干活有 shell 权限。请用你对待任何最终进入执行上下文的输入的同一种
  怀疑，来对待 plan 内容。
- **任何从 shell 能碰到的东西。** 编辑/写入守卫是防事故的**纪律守卫**，不是围栏 ——
  shell 命令不受工具级钩子约束。

## 报告漏洞

请在仓库上开一个**私密安全公告**
（<https://github.com/YongmaoLuo/Product-Development-Team/security/advisories/new>），
而不是公开 issue。请附上版本或 commit、攻击者能获得什么，以及你手上最小的复现。

这是个人项目而非有资金支持的项目，所以没有漏洞赏金，也没有承诺的响应时限 —— 但报告
会被读，真问题会被修，而不是被辩论掉。

## 这个项目怎么审计自己

仓库里有一份安全审计文档 `SECURITY_AUDIT.md`。它是**构建输入**，不是一篇记录：其中
好几道测试门禁会解析它并对它的结构做断言，而改动归因门禁要求**对源码的改动能被追溯
到其中的某一条目**。

它记录的是**缺陷及其修复** —— 问题的形状、修了什么、怎么验证这个修复。它刻意不记录
任何特定机器上发生过什么：计数、时长、暴露窗口，读者读源码是**推导不出来**的，所以
公开它们有成本而没有收益。

同一条线把这份审计拆成了两半。凡是描述**排查过程本身、而不是软件本身**的东西 ——
带日期的墙钟基线、哪几格（问题类 × 面）查过而一无所获的网格、逐条 grep 及其处置的
表格 —— 都是围绕产出这些条目的过程所做的记账。它们一条都无法从源码推出，而其中的
否定结果那一半更是一张「哪里没人找到过东西」的地图，而「没人找到过」的地方正是
「以后也没人去看」的地方。所以它放在 gitignored 的 `.config/` 下，属于操作者本机：
全新 clone 里没有这些东西，解析它的 meta-test 在那里是 **skip 而不是 fail**。
`SECURITY_AUDIT.md` 保留档位定义、条目模板、全部条目，以及两个**确实在陈述本仓**
的附录 —— 改过哪些测试、审计授权改了哪些源码文件。

这条线是被**强制执行**的，不只是被声明：公开文档里一旦出现采集日期、套件基线数字、
否定结果单元格、或那几节的标题，静态门禁就会把构建打红。

如果你要往里加东西，工作规则在[贡献](development/contributing.md)：写对软件成立的
东西，不要写对你的机器成立的东西。
